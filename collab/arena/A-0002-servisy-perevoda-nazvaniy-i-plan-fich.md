Опорные точки архитектуры, на которых стоят оба блока:

# A. Сервисы перевода названий

## A0. Что и сколько переводим

- ~200 названий/день (пик — экран поиска, 20-24 карточки за один ответ).
- Средний заголовок YouTube — 40-60 символов; 200 × 55 ≈ **11 тыс. симв./день**,
  ≈ 330 тыс./мес. При 1000 названий/день — 1.65 млн симв./мес.
- Текст «плохой» для NMT: смесь языков (`ОБЗОР iPhone 17 Pro — честно`),
  CAPS, эмодзи, бренды, номера серий, имена каналов рядом.
- Экономика решается кэшем, а не тарифом: одна и та же карточка показывается
  десятки раз; при TTL 30 дней реальный объём падает в 3-5 раз.

## A2. Качество на коротких заголовках (что реально ломается)

| Проблема | NMT (Google/DeepL/Yandex/Azure) | LLM с промптом |
|---|---|---|
| Бренд/латиница (`iPhone`, `Dota 2`) | DeepL/Google склоняют к транслиту: «Айфон», «Дота 2» | держит латиницу по инструкции |
| CAPS (`ЭТО КОНЕЦ`) | DeepL сглаживает регистр | сохраняет по инструкции |
| Эмодзи | Google сохраняет, DeepL может выкинуть, Azure сохраняет | сохраняет |
| Смешанный язык (`ОБЗОР iPhone`) | переводит ВСЁ, включая русскую часть → ломает смысл | «переводи только нерусские фрагменты» |
| Имя канала в заголовке | переводит | по инструкции не трогает (в запрос имя канала и не кладём) |
| Длина | обычно короче и «литературнее» | может раздуть, нужен лимит символов |
| Пояснения/кавычки | нет | бывают → нужна строгая схема ответа + валидация |

Отдельно: NMT не понимает, что перед ним заголовок, и добавляет точку/меняет
тире; DeepL с `preserve_formatting=1` ведёт себя приличнее. LLM с
`temperature=0` и JSON-схемой даёт самое предсказуемое поведение на смеси.

## A3. Шорт-лист и рекомендация

1. **Дешёвый — Yandex Cloud Translate.** $5.74/1M, 1M симв./мес бесплатно,
   оплата в рублях, доступ без прокси из РФ, лучший RU↔EN среди NMT.
   Минус: на смешанных заголовках переводит и русскую часть.
2. **Качественный — LLM-шлюз** (Gemini 2.5 Flash-Lite как рабочая лошадка,
   GPT-4o-mini как второй). Не «сервис перевода», а один прокси, который
   прячет провайдера, ключ и формат; качество на смеси/брендах/эмодзи лучшим
   образом управляется промптом, цена на 1-2 порядка ниже NMT.
3. **Без ключа/self-host — LibreTranslate на VPS.** Свой инстанс: нет
   вендорского аккаунта и ключа, полный контроль, ~€5/мес. Минус: качество
   Argos-моделей на заголовках заметно хуже (бренды ломает), батча нет
   (24 названия = 24 запроса).
   *Не* Lingva/MyMemory: это скрейп/лимиты без SLA и с прямым нарушением ToS
   апстрима — в клиент такое встраивать нельзя.

**Рекомендация.** Основной — LLM-шлюз, потому что он же решает вторую задачу
блока B (перевод поискового запроса и нейро-поиск идут через тот же эндпоинт).

Fallback-цепочка `/title_tr`:

```
1. кэш L2 (мост)  -> hit: отдаём сразу, 0 запросов
2. LLM-шлюз       -> 8 с таймаут, валидация, при провале item -> в след.
3. Yandex Cloud   -> 6 с таймаут (если ключ есть)
4. DeepL Free     -> только для пар en/de/fr->ru, 6 с (если ключ есть)
5. ничего         -> оригинал + negative cache 5 мин, маркер НЕ ставим
```

Правило проекта: на любом шаге «не вышло» → возвращаем **оригинал**, а не
пустую строку и не транслит (unknown beats wrong). Кэшируем только успешный
перевод, который прошёл валидацию.

## A4. Контракт `POST /title_tr` (на мосту, `127.0.0.1:8013`)

```http
POST /title_tr
Content-Type: application/json
{"v":1,"lang":"ru","items":[{"id":"dQw4w9WgXcQ","t":"Never Gonna Give You Up"},
                            {"id":"oKIkvEjI2WE","t":"ОБЗОР iPhone 17 Pro"}]}

200 {"ok":1,"lang":"ru","ms":142,"c":1,
     "tr":[{"id":"dQw4w9WgXcQ","t":"Никогда не сдадимся","src":"en","s":"llm","c":1}],
     "skip":[{"id":"oKIkvEjI2WE","why":"has_cyrillic"}],
     "fail":[{"id":"…","why":"quota"}]}

400 {"ok":0,"why":"bad_json"}
429 {"ok":0,"why":"rate"}            + Retry-After
503 {"ok":0,"why":"no_key"|"upstream"|"timeout"}
```

Правила:

- ≤ 24 items, ≤ 120 симв. на item, ≤ 2400 симв. суммарно, тело ≤ 16 KB
  (иначе `413`; JS режет пачками сам);
- `id` нужен для кэша и для DOM-маркера; для плейлистов/каналов — `p:<id>`,
  `c:<id>`, чтобы один эндпоинт закрыл и их;
- JS не отправляет строки, где ≥ 60 % кириллицы (см. A8) — экономит квоту;
- мост дедуплицирует одинаковые `hash(t)` внутри запроса и в полёте
  (на экране поиска клиент дёргает 2-3 запроса подряд с общими карточками);
- один медленный апстрим не блокирует звук: сервер моста — поток на соединение
  (`Bridge.java:serve/handle`), но `handle()` уже ставит `setSoTimeout(20000)`,
  `/title_tr` должен иметь **свой** таймаут 8 с и не занимать общий лок;
- `GET /title_tr/status` → `{"ok":1,"provider":"llm","quota":"ok","cache":{"n":4210,"hit":0.71}}`
  для пункта «Статус» в нашей панели (`vot.js:2925-2960`);
- `POST /title_tr/reset` — ручной сброс кэша (пункт в панели), нужен, когда
  сервис выдал мусор.

## A5. Где живёт ключ

Только на мосту, по образцу OAuth-токена Яндекса: файл в `sDataDir` рядом с
`vot_config_cache.json` (`Bridge.java:219-230`) — например `title_tr.json`
(`{"provider":"llm","url":"https://...","key":"...","model":"gemini-2.5-flash-lite"}`).
В инжектированный JS не попадает **ничего**, кроме `{"ok":1}` и текстов: JS на
странице видит только результат. Если ключа нет — `/title_tr` отвечает
`503 no_key`, оверлей один раз пишет в лог и больше не спрашивает (backoff
10 мин), карточки остаются с оригиналом.

Для LLM предпочтителен собственный прокси (как `worker` в
`vot_config.json`): он же прячет провайдера, снимает проблему гео (Google
Cloud/Azure из РФ требуют не-RU платёжку), даёт один формат ошибок и позволяет
менять модель без пересборки APK.

## A6. Кэш и инвалидация

Два уровня, оба по **хешу исходного текста**, а не по videoId:

- **L1 в JS** (`vot.js`, рядом с `state`): `Map` `lang|hash(t)` → `{t,at}`,
  TTL 6 ч, cap 400 записей, чистится на смене ролика/страницы.
  Нужен, чтобы прокрутка сетки не дёргала мост.
- **L2 на мосту**: `title_tr_cache.json`, ключ `v1:<lang>:<sha1(src)>` →
  `{t, src, at, hits}`, TTL 30 дней, LRU 5000 записей, файл ≤ 512 KB,
  запись атомарно (tmp + rename), флаш не чаще раза в 2 с.
  Хеш, а не videoId: одно и то же название у разных роликов (сериалы, нумерация
  серий) переводится один раз; при смене названия хеш меняется сам.

Инвалидация: (1) хеш не совпал; (2) TTL; (3) смена `lang` или провайдера —
версия схемы в ключе; (4) ручной сброс из панели; (5) **не** кэшируем, если
перевод пустой, равен оригиналу или не прошёл валидацию (иначе «навсегда
оригинал»); (6) negative cache (fail) — 5 мин, только на мосту.

## A8. Промпт и параметры

LLM — system-промпт (один раз на батч, ~180 токенов):

```
Ты переводишь названия видео YouTube на русский. Верни СТРОГО JSON
{"tr":[{"i":<индекс>,"t":"<перевод>"}]} без markdown и пояснений.
Правила: одна строка; имена собственные, бренды и латиницу-бренды
(iPhone, Dota 2, NVIDIA) не переводить и не транслитерировать; эмодзи
сохранять на том же месте; КАПС сохранять; числа, годы, номера серий не
менять; если фрагмент уже по-русски — оставить как есть; длина не больше
исходной +30 % и не больше 100 символов; никаких кавычек вокруг всего
названия, никаких «перевод:».
```

Плюс: `temperature=0`, `max_tokens ≈ 2×входа`, JSON-режим
(`response_format=json_object` у OpenAI, `responseMimeType=application/json`
у Gemini), валидация после ответа:

- число элементов = числу входных (иначе — по индексам, отсутствующие → fail);
- нет `\n`, нет «перевод», нет кавычек по краям, длина ≤ 100;
- доля латиницы не выросла относительно оригинала (иначе подозрение на
  «не перевёл»/транслит → fail);
- совпало с оригиналом и оригинал не русский → fail (не кэшировать).

NMT-fallback (Yandex/DeepL): `source_lang=auto` (DeepL требует явный —
берём детект из `langBase` заголовка или `en`), DeepL
`preserve_formatting=1`, батч 50 текстов; Google — `mimeType=text/plain`.
Глоссарий брендов (DeepL glossary / Yandex glossary) — 20-30 строк, окупается.

Детект «уже русский» в JS, до отправки: доля символов `[А-Яа-яЁё]` среди букв
≥ 0.6 → `skip`. Дешёво, без сервиса, снимает половину трафика на RU-контенте.

## A9. Риски блока A

- **Гео/оплата**: Google Cloud и Azure из РФ — проблема платёжки, DeepL может
  быть недоступен; Yandex и свой прокси — нет. Закладывать прокси сразу.
- **ToS**: NMT/LLM-API разрешают встраивание, но запрещают перепродажу
  «как сервис перевода» — мы не перепродаём. Скрейперы (Lingva/MyMemory)
  в клиент не берём.
- **Галлюцинации LLM**: закрываются валидацией из A8 + правилом «оригинал при
  провале»; поэтому маркер ставится только после успешной валидации.
- **Приватность**: уходят только названия (публичные) и videoId; описания,
  имена каналов и историю не отправляем.
- **Нагрузка на мост**: батч 24 и дедуп в полёте; при 3 параллельных
  запросах с экрана поиска — один апстрим-вызов.

## B2. По фичам

**1. Разные настройки для разных аккаунтов.** Сейчас всё в одном объекте
`localStorage['vot-ui-prefs']` (`vot_ui.js:10, 23-37`), читается через
`uiPref` (`vot.js:2237`). Ключ пространства — `ytcfgGet('DATASYNC_ID')`
(`vot.js:674`), fallback `guest` (пусто/выключенный аккаунт). Схема:
`vot-ui-prefs:v2 = {"<ns>": {...}}`, старый плоский объект при первом чтении
переезжает в `ns` текущего аккаунта (одна миграция, без потери настроек).
На мосту так же надо разделить `vot_config_cache.json` по аккаунту — иначе
OAuth-токен одного профиля уедет в другой. Объём S, риск низкий.
Не забыть: `DATASYNC_ID` меняется при выходе/входе — это нормально, это и есть
граница «другого аккаунта».

**2. Регион.** `gl` не наша переменная: его держит cookie `PREF` профиля и
аккаунт. Менять из JS «на месте» (`document.cookie`) ненадёжно: Cobalt хранит
куки в своём профиле, а YouTube TV берёт регион ещё и из аккаунта. Рабочий
путь — навигация `…/results?search_query=…&gl=RU&persist_gl=1` (то же для
главной) и пункт в панели со списком стран. Цена: полная перезагрузка страницы
→ умирает текущий перевод (мост надо честно остановить `POST /stop`), теряется
состояние панели. Объём M, риск средний: нельзя трогать аккаунтный `PREF`
глобально, иначе «регион поменялся везде, включая телефон».

**3. Перевод названий + маркер.** Два пути:
*DOM* — искать карточки по `a[href*="/watch?v=ID"]`, класть `span` с переводом
рядом с оригиналом (или подменять текст) и бейдж; борется с перерисовками и
виртуализацией (нужен `MutationObserver` + ключ по videoId).
*JSON* — в `vot_net.js` на ответах `/youtubei/v1/search` и `/browse`
(`patchFetch`/`patchXhr`, `1075`/`1027`) рекурсивно обойти JSON, собрать
`{videoId, title.runs[0].text}`, отдать батч в `/title_tr` и **подменить текст
до отдачи странице**. Клиент рендерит уже переведённое — ни мерцания, ни
борьбы с виртуализацией, `accessibilityData.label` оставляем оригинальным.

Рекомендуется JSON-путь + DOM только для бейджа:
1. если весь батч пришёл из L2-кэша (5-20 мс) — подменяем синхронно;
2. иначе — отдаём ответ как есть, переводы приходят асинхронно и
   подставляются DOM-проходом по `videoId` (и греют кэш для следующего раза).
Так сетка никогда не ждёт сеть, а «второй заход» уже мгновенный.
Объём M, риск средний (размер JSON 300-800 KB → обход с лимитом узлов и только
для search/browse, не для player).

**4. Системная клавиатура.** Cobalt рисует свою OSK (`SbSystemKeyboard`);
Android-IME требует `onCreateInputConnection`/`showSoftInput` в нативной части
Starboard, то есть патча Cobalt внутри APK, а не инжекта. Наш `<input>` в
оверлее поднимет **ту же** OSK Cobalt, а не системную — выигрыша нет.
Вердикт: только нативный слой, объём L, риск высокий (сборка Cobalt, фокус,
жесты). Не в первую очередь.

**5. Перевод поискового запроса.** Точка уже есть: `searchRewrite`
(`vot_net.js:1000-1012`) правит тело `POST /youtubei/v1/search` и уже
отказывается, если есть `continuation`. Добавляем второй шаг: если включена
опция «переводить запрос» и `query` содержит латиницу — заменить `j.query`
(или, безопаснее, показать в панели «Перевести запрос» и навигировать на
`results?search_query=<перевод>`). Второй вариант не ломает историю и
позволяет вернуться к оригиналу. Объём S. Риск: двойной перевод при
back/forward и «перевод брендов» — лечится словником «не переводить»
(он же глоссарий из A8).

**6. Штатные фильтры.** Уже реализованы: `setupSearchFilters`
(`vot.js:3525-3545`, группы «Сортировка/Дата/Тип/Длительность») + protobuf
`params` в `vot_net.js:879-1010`. Это **не фича, а «не сломать»**: любые работы
по поиску (5, 9) идут через тот же `searchRewrite` — новые правки обязаны
сохранять `params` байт в байт и не пересобирать поле 2 (комментарий в
`vot_net.js:926`). Расширять — только добавлением значений в `GROUPS`.

**7. Сайдбар.** Штатный `ytlr-guide` — нативный список, который клиент
перерисовывает; вставка своих узлов в него — та же ловушка, что с карточками,
но без стабильных якорей. Реально: своя панель (как `#vot-ui-root`,
`vot_ui.js:44+`) с разделами «Плейлисты / Каналы / Мои списки», записи —
массив `{title, url, kind}` в префах, переход навигацией
(`/playlist?list=…`, `/@channel`, `/results?search_query=…`). «Свои списки» —
локальный массив videoId → открытие первого + автоплей следующего (это уже
почти плейлист, объём растёт). Объём M, риск средний (фокус/OK в панели уже
отработан в `FOCUS_CTRL`, `vot.js:3319`).

**8. Long-press.** 8a — тайм-коды: в описании ролика регуляркой
`(?:^|\s)(\d{1,2}:)?\d{1,2}:\d{2}(?:\s|$)` собрать главы, показать в панели,
переход по `&t=`. Дёшево и полезно само по себе (S).
8b — «что это за фильм»: из заголовка LLM-ом вытащить название/год, отдать
ссылку на поиск (тот же `/title_tr`-прокси, другой промпт). M.
8c — поиск в установленных кинотеатрах: только нативно (`PackageManager`
+ известные deeplink'и: `kinopoisk://`, `ivi://`, `okko://`, `wink://`,
`kion://`, `more.tv://`), плюс `Intent.ACTION_SEARCH` как общий случай.
Таблица deeplink'ов живёт в нативном коде и требует обновлений; приложения без
deeplink'а — не находятся. L, риск высокий (падения чужих приложений,
разрешения, `queryAllPackages` на новых Android ограничен).
Long-press: `keydown` с таймером на OK (kc 13/23) — уже есть обработчик
(`holdPending`, `vot.js:3345`), но новый перехват обязан проверять
`focusOwnsKey()` и не съедать OK при `holdPending()`.

**9. Нейро-поиск.** 9a — перехватить готовый запрос: голос на ТВ приходит как
обычный поиск (`results?search_query=…`, в InnerTube — `query`), поэтому в
`searchRewrite` можно нормализовать его LLM-ом («приведи к короткому
поисковому запросу на языке оригинала/английском»): «это где мужик с собакой
спасает людей» → `man saves people movie` → выдача. Второй вариант — не
подменять на лету, а показать чип «Искать: <перевод>» и дать нажать OK
(безопаснее для смысла). M.
9b — свой микрофон: нативно `SpeechRecognizer`/`RecognizerIntent` (нужны
разрешения и обработка фокуса), текст → тот же путь. L, и на Tizen/Android
поведение разное. Начинать с 9a: он проверяет ценность идеи без нативного кода.

## B3. Roadmap

**Фаза 1 — «почти бесплатно и без риска» (всё в JS + мост, звук не трогаем).**
`5` перевод запроса (S) → `3` названия + маркер (M, требует A) → `8a` тайм-коды
(S) → `1` префы по аккаунту (S). Обоснование: три фичи живут в одном хуке
(`searchRewrite` + ответный хук), а маркер — единственный визуальный риск,
поэтому его делаем после того, как `/title_tr` уже стабилен в логах.

**Фаза 2 — навигация и поиск.** `9a` нейро-поиск (M) → `2` регион (M) →
`7` сайдбар (M) → расширение `6` (S, если попросят). Обоснование: 9a и 2 —
это навигация/перезагрузка, их нельзя делать одновременно с работами по
карточкам (перезагрузка сбрасывает состояние и мешает логам).

**Фаза 3 — нативное.** `4` IME (L) → `8b/8c` агрегаторы (L) → `9b` микрофон (L).
Обоснование: всё требует сборки нативного слоя и не влезает в инжект; каждая
фича ломает фокус/OK, поэтому по одной.

## B4. Что требует чего

**Ключи/аккаунты:** фича 3 и 5, 9a (LLM-прокси + опционально Yandex/DeepL),
8b (тот же прокси). Ключ — только в `title_tr.json` на мосту (A5).

**Нативный код:** 4 (IME), 8c (кинотеатры), 9b (микрофон), частично 2
(если понадобится менять cookie-профиль вместо навигации).

**Может сломать существующее:**
- *перевод звука* — любой новый сетевой хук на `/youtubei/v1/player` и на
  `googlevideo.com` опасен: `onPlayer`/`rememberSabr`/`rememberAudio` кормят
  `fetchMeta`/`sabrParamsFromCfg`. Хук названий — **только** search/browse;
- *панель фильтров* — `searchRewrite` правит то же тело, что фильтры; менять
  `params` нельзя, только добавлять `query` и только при явной опции;
- *OK на пульте* — новый long-press/хоткей обязан уважать `focusOwnsKey()`
  (`vot.js:3319-3343`) и `holdPending()` (`3345`), иначе вернётся баг «OK
  съедал первое нажатие»;
- *громкость* — не трогаем `enforceVolume` (частый тик 250 мс).

## B5. Маркер переведённого названия (10-foot UI)

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Иконка/бейдж после заголовка** (`RU`, глобус) | однозначно, видно на любом фоне, не мешает тексту | ширина: длинные названия и так обрезаются, бейдж могут «выдавить»; нужен глиф в шрифте ТВ |
| **Цветная точка / полоска слева** (2-3 px, на всю высоту строки) | не занимает ширины, не ломает обрезку, спокойно читается с 3 м | легко спутать с «просмотрено»/LIVE/прогрессом; плотная сетка = рябь |
| **Цвет текста** (приглушённый/акцентный) | 0 ширины, 0 новых узлов | конкурирует с фокусом (белая рамка/подсветка съедает оттенок), на дешёвых матрицах не видно |

**Рекомендация:** полоска слева + `aria-label`/`title` с оригиналом; бейдж
`RU` — только если полоска не читается на реальном ТВ (проверить на `.100`).
Полоска реализуется как `border-left` на самом текстовом узле (не новый
элемент → не влияет на layout и на расчёты обрезки клиента), цвет — один
акцентный, маркер снимается вместе с переводом.

Правило: маркер ставится **только** если перевод реально применён и прошёл
валидацию; при ошибке сервиса/таймауте — оригинал без маркера, а не наоборот.
